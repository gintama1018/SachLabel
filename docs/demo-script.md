# Demo Script — Live Judge Demo
Target: ~60–75 seconds. Practice against a real stopwatch, not a guess.

---

**[0:00–0:10] — Hook, no app open yet**

> "Every one of you has bought something because the front of the pack said 'natural,' 'sugar-free,' or 'pure.' Nobody reads the back. We built something that does — and tells you when the front is lying to the back."

**[0:10–0:15] — Open app, show home screen**

> "Two photos. Front, then back."

**[0:15–0:30] — Live capture on a real product with a known contradiction**

Capture front → capture back → processing screen visible (don't skip this — the "Reading label… Checking claim…" feedback is part of the trust story).

**[0:30–0:45] — Result screen**

> "Front says '100% Natural.' Back — right here, exact quote — has a qualifying disclaimer most people never read. We're not making this up. That's the product's own text, cited."

Tap 🔊 Listen — let the TTS play at least the first sentence out loud.

> "And this plays out loud, in the user's own language — because a huge number of the people this actually matters to don't read the fine print fluently, or at all."

**[0:45–0:55] — Opt-in health layer (quick)**

Tap "Want to check what this means for you?" → select a preset (e.g., diabetic).

> "This part is optional, and it's careful on purpose — informational only, never a medical yes/no. We're not trying to be a doctor. We're trying to make sure you have the words in front of you that the package already legally has to give you."

**[0:55–1:05] — Closing line**

> "Every claim on the market is basically a database lookup for the big scanner apps. We're the first to actually read the package's own words against itself. Same data the brand already published — we just make sure you see all of it, not just the big font."

---

## Backup plan if live capture fails
Pre-load one known-good result screen as a static fallback screenshot/recording. State explicitly: *"Here's a result from a test run in case the lighting here doesn't cooperate"* — honesty about a live-demo limitation reads better than a silent fumble.

## Products to demo with (see qa-checklist.md for the full test list)
Pick a product you've tested at least 3 times successfully before the actual demo slot. Don't demo on a product you're seeing for the first time in front of judges.
